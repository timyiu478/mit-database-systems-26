SQL -> Procedural Plan -> Optimized Plan -> Compiled Program

logical data independence:

* freedom to change the schema
* Do we have to rewrite the application queries if we add a new column to the table?

physical data independence:

* freedom to change the storage without changing the query
* If we store the table as B-tree index, does it break the application queries?

Relational Data Model + SQL:

* support Many to Many relationships without redundancy
* Declarative query language
* physical representation of the data is not specified
* How does it provide logical data independence?
    * View(virtual table): maps old schema to new schema so that the old programs/queries can work
        * My understanding: can think view as a PROXY
        * Cannot have a view and a table with the exact same name
            * If we want to modify the exiting table e.g. animal table without break the old program,
            * we can rename animal to animal1 and then create a view called animal

View Example:

```
CREATE VIEW cage_count as 
(SELECT cageno, count(*)
FROM animals JOIN cages ON cageno=no
GROUP by cageno
)
```
